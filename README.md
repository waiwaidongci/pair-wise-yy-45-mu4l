# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + RTK Query + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 多窗口协作与冲突合并

多个窗口（或多人同时打开同一件样衣）评审时，不再整包覆盖彼此的修改：

- **按提交人 + 时间追加合并**：批注、评审草稿、替代方案都是追加实体，携带提交人、窗口标签（窗口 A/B…）与时间戳，归并时按时间排序。
- **同部位双批注都保留**：同一部位的多份批注分组展示，分别标注来源窗口、提交人和时间，后保存不会盖掉先保存。
- **本地待并入 + 显式同步**：新改动先存为本窗口待同步项（侧栏与页面顶部有计数），点「同步并入」才共享；每条可单独放弃。
- **重复同步幂等**：每条提交有全局唯一 id，重复点击同步 / 崩溃重试 / 日志重放都只生效一次。
- **崩溃恢复**：输入与待同步改动防抖写入「最近完整草稿」检查点；异常退出后重开弹窗询问恢复或放弃，正常关闭则静默恢复未同步项。
- **审核锁定保护**：锁定前若有本地改动未并入，必须先逐条核对并选择「放弃」或「另存修订」；锁定提交本身带待办校验，防绕过。
- **锁定快照不可变**：锁定瞬间深冻批注、方案与草稿；锁后新批注/翻案决定不进入快照。已采纳方案只有第一个决定生效，之后无法改动其依据；解锁开启新修订分支。

存储布局见 `src/features/collab/storage.ts`，合并规则见 `src/features/collab/materialize.ts`。
